# 设计补充：开放性、兼容性与风险评审

状态：待评审。用户已明确下一步继续完善设计，暂不写功能代码。本文不批准任何实现，也不将实验模块作为选型依据。

## 1. 如何避免“看似插件化，实际锁死”

| 需要稳定的边界 | 宿主承诺 | 暂不承诺 |
|---|---|---|
| 内容 | 可导出Markdown、元数据与附件清单；停用插件后原文仍可读 | 任意富文本结构无损转成Markdown |
| 提供者 | 相同接口可替换；多提供者显式选择；错误/预算语义统一 | 任意提供者性能与结果完全相同 |
| UI贡献 | 命名槽、稳定贡献ID、异常隔离、可撤销 | 任意修改宿主DOM/全局样式、依赖内部组件结构 |
| 用户组件 | schemaVersion、已支持block、固定release快照 | 执行自定义JavaScript、任意网络和数据库访问 |
| 检索索引 | 从原始来源与版本重建，记录模型与索引代际 | 不同embedding模型索引原地兼容 |
| 持久化 | 显式迁移、导出恢复与存储边界 | 不经测试即可从SQLite切到PostgreSQL |

插件数据分为三类：用户原始内容（宿主拥有可携带格式）、可重建派生数据（记录来源/算法版本）、插件配置（独立schema与迁移）。卸载不默认销毁原始内容，派生产物清理由宿主确认执行。

## 2. 兼容策略必须具体到失败行为

- 插件API不兼容：拒绝激活并保留安装配置，显示原因；不得半加载。
- 配置迁移失败：保留旧配置与旧release，不自动写空配置继续启动。
- 首页引用缺失或撤架组件：显示占位、允许移除或替换；其它组件仍可用。
- Markdown包含未知语法：保留源文本；不为渲染便利永久丢弃内容。
- 模型/索引切换：新索引就绪后切换读取；旧索引可保留到验证完成，不混算分数。
- 服务升级：数据库迁移与代码兼容窗口须明确；“回滚二进制”不等于能回滚不可逆数据迁移。

## 3. 应该采用多少基础设施

第一版建议只需要Web应用进程、关系数据库与附件目录。任务处理可以同进程但必须可恢复；模型调用必须异步并设置并发上限。遇到需求再增加组件：

- 多实例部署需要共享数据库、会话与任务领取机制，不能仅多启动几个SQLite进程。
- worker隔离有实测必要时才独立进程；Redis不是幂等、版本校验与权限控制的替代品。
- 远程第三方代码不是一个普通插件类型开关，而是独立安全产品。
- 不为每个模块预建接口工厂、事件总线和通用基类；通过直接服务调用与小型协议保持可读性。

## 4. 高优先级风险与验收证据

| 风险 | 设计约束 | 需要的证据 |
|---|---|---|
| 跨用户知识泄漏 | 原始caller+scope贯穿检索/历史/附件/模型上下文 | 两用户资源矩阵与浏览器端到端测试 |
| AI/后台任务覆盖新内容 | revision CAS、attempt检查、来源有效性复核 | 并发更新/删除/重试交错测试 |
| 市场审核后偷换内容 | 不可变release、内容摘要、安装固定版本 | 草稿修改不改变已发布/已安装快照 |
| 管理员身份被抢注 | 受信部署初始化，不以公开用户名列表直接赋权 | 未持初始化凭证注册无法获得管理员 |
| 恶意组件窃取数据 | 声明式数据、受信renderer、无任意代码 | schema负例、XSS与越权引用测试 |
| 模型端点导致SSRF | 宿主允许目标、DNS/重定向/连接策略 | 私网IPv4/IPv6、重绑定与重定向测试 |
| 升级损坏私人知识 | 迁移前备份、事务、保留源格式 | 旧版本样本迁移与恢复演练 |
| 依赖堆积/弃维护 | 小依赖面、锁版本、定期审计、替换边界 | 引入每个新包的ADR或明确收益说明 |

## 5. 下一轮设计需要深化而不是直接编码的部分

1. **认证选型**：成熟认证库/OIDC/内建密码的成本比较；注册策略、重置密码、邮件依赖和管理员初始化。实验scrypt仅证明机制，不替代完整账号生命周期。
2. **生产部署**：确认自托管/托管优先后选择数据库、HTTPS与配置模式；不同时承诺所有部署方式。
3. **组件协议**：用读书卡、研究工作台、个人首页三个真实用例验证block边界与动态数据授权，不先造可视化编程语言。
4. **知识真相模型**：人工页面与来源导入分开；AI派生产物是否独立页面、引用如何撤回、恢复删除资料是否恢复旧索引，需要明确交互。
5. **MVP容量预算**：选择真实目标机器、用户/文档量与测试集后再定量，不凭空声称高并发或毫秒响应。

## 6. 设计通过条件

文档之间不存在互相矛盾的身份、存储、发布或插件信任模型；关键决策包含替代方案和退出成本；每个MVP需求都能对应一个用户流程、模块、持久化实体与验收项；延期能力明确标注。设计评审通过前，任何实验代码都不得被升级为正式完成项。
