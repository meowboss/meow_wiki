# Meow Wiki：会生长的个人知识宇宙

> 状态：首个架构提案 + 本地纵向原型。这里明确区分愿景、已实现能力、上线门槛，避免把设计画成已经完成的产品。

## 1. 我们到底在创造什么

不是再做一个 Markdown 文件夹，也不是在传统 Wiki 旁边塞一个聊天框。

**Meow Wiki 是一个由用户自己装配的知识空间：内容属于用户，页面可组合，AI 有证据，扩展有边界。** 每个用户从开箱即用的官方插件集开始，逐渐长出自己的主页、研究室、项目百科、读书花园，甚至成为别人可安装的知识体验作者。

### 三个产品支柱

1. **我的知识花园**：专属空间、页面树、链接与反向链接；可导出、可恢复、可迁移。
2. **有证据的知识伙伴**：回答能回到来源；AI 修改先提出草稿和差异，由用户确认，不静默覆写原文。
3. **可创作的体验市场**：模板 → 声明式页面组件 → 隔离运行的高级插件。私有创作和公开传播是两个不同的生命周期。

### 值得探索的“有趣”方向

- 知识星图：不是炫目的力导向图，而是能回答“这个结论从哪里来、哪些旧笔记受影响”。
- 研究工作台：材料、引文、问题、草稿共处一个页面，不必来回跳聊天窗口。
- 时间胶囊：按历史版本回答“我三个月前怎么理解它”，与当前观点对照。
- 知识养护：断链、陈旧来源、互相矛盾的结论进入待办，不自动删改。
- 可分享的知识配方：发布阅读卡、项目复盘、学习地图组件，而不是复制整套账号配置。
- 人与 AI 共写：每个提议带来源与预期版本，支持接受、局部接受、拒绝和撤回。

这些是方向，不进入首版强制清单。

## 2. “一切皆插件”的精确定义

**业务能力可替换，安全与数据不变量不可绕过。** 不把登录、授权、事务和审核强制做成可以任意卸载的用户插件。

```text
React shell（当前固定布局；未来命名 UI 槽）
       │ HTTP / 共享数据契约
Host ──┼─ 身份与 workspace 授权
       ├─ 持久化、输入限制、错误边界、版本/迁移
       ├─ 插件目录与每空间安装状态
       └─ 能力注册表
             ├─ official.markdown → render
             ├─ official.search → search
             └─ official.llm-wiki → ask → 依赖 search

用户组件 → 纯文本声明式数据 → 只能作为模板使用
未来不可信代码 → 独立隔离执行器 → 宿主 capability broker
```

### 当前选择：模块化单体，不做分布式系统

TypeScript + React + Vite + Fastify + Zod + SQLite。前后端使用同一种语言，减少初始维护面；成熟库负责 HTTP、输入验证、Markdown 与 HTML 清洗。不自建 Markdown 解析器、ORM、向量库、任务集群或动态模块下载器。

当前使用 Node 24 内置 `node:sqlite`（仍有实验性提示），同步小事务和 workspace JSON 快照适合本地原型，**不是最终高并发数据模型**。独立 `Store` 边界允许下一阶段迁往关系表，生产多实例需求出现时再用 PostgreSQL。不可把一次 JSON 保存误称完整 revision 历史。

### 内核现状

- manifest 校验：id、apiVersion=1、version、kind、requires。
- 只加载源码静态导入的受信官方插件；重复 ID / 能力拒绝注册。
- 初始化时暂存服务，失败不泄漏半注册状态。
- 每空间启停只改变能力可用性；检查依赖，失败事务回滚。
- **不是热卸载**：当前插件是无资源纯函数，不提供异步 setup、定时任务、disposer、UI 贡献、第三方包安装。出现第一种有副作用插件前，必须补归属清理作用域与生命周期测试，不能先许诺支持。
- 前端目前是固定 shell，并未实现动态 UI 插件槽；未来首批只加 `nav.items / editor.toolbar / page.actions`。

## 3. 两条扩展轨道：不能混为一谈

| 轨道 | 当前能力 | 信任方式 | 公共分发 |
| --- | --- | --- | --- |
| 官方插件 | 代码、服务提供者、启停 | 开发时审阅、静态打包 | 随产品发布 |
| 用户组件 | 名称、说明、纯文本模板 | 仅当数据；不 eval、不执行 HTML/JS | private → pending → published/rejected |
| 高级第三方插件 | 尚未实现 | 独立进程/容器或跨源 iframe + 受限 RPC，另做威胁建模 | 签名包、不可变版本、权限授权、撤回机制后开放 |

用户组件默认私有。提交不会自动上架。当前 `Store.review` 是受信内部服务方法，**没有公网审核接口或审核后台**；单元测试验证它发布后其他身份才可安装。创建/提交请求无法注入 status 或 authorId。安装的数据不会变成可执行代码。

市场正式上线前必须具备：不可变版本和内容摘要、审核人身份/角色、审核审计、拒绝原因、作者修改后重新审核、包依赖/许可证/资源扫描、撤架、用户固定版本及升级确认。此阶段不引入完整工作流引擎。

## 4. 身份、资源与安全

### 已实现

- 本地模式只绑定 127.0.0.1，固定宿主身份，禁止根据请求中的 user header 改身份。
- token 模式要求宿主配置用户与至少 32 字符令牌；所有 API fail closed。它是脚本入口，不是多人账号系统。
- 仓储查询使用 owner + workspaceId；搜索只接收授权后的页面集合，页面写入也只能命中该空间。
- 无 CORS，检查 Origin，响应设置 CSP/no-store/nosniff；Markdown 用成熟 sanitizer 清洗，不直接输出原始 HTML；暂禁远程图片以避免阅读跟踪。
- 参数长度、body 大小、每空间页面/组件数量有原型上限。

### 尚不具备的生产保证

登录/OIDC、会话轮换、多用户路由、组织角色、数据库 RLS、公开分享、速率限制、细粒度配额、审计、备份恢复工具、安全审计尚未完成。不能开放反向代理把 local 模式发布到公网；token 模式也不等同生产部署加固。

网络、文件、密钥与模型调用未来由宿主 broker 统一实施权限，不能把 manifest 写着 permissions 当沙箱。浏览器 Worker 与同进程 facade 也不构成恶意代码安全边界。

## 5. 知识模型与 AI 演进

### 目标实体（按需求逐批落库，不一次生成所有表）

- User / Workspace / Membership：身份、空间与成员关系。
- Page / PageRevision / Link：人工页面、不可变历史与连接。
- Source / SourceRevision / Artifact / Citation：原始材料、版本、派生产物、来源定位。
- Job：stage、attempt、expectedRevision、状态、幂等键与错误。
- PluginRelease / Installation / ComponentRelease / Review：分发与治理。
- ModelProfile：provider、model、endpoint、capabilities、预算、secretRef，不将明文 key 交给插件。

### 来源管线（下一阶段）

```text
授权 → source revision → queued → parsing → chunking → indexing → ready
                      └──── failed / cancelled / deleting
```

产物以 `(workspace, source, revision, stage)` 幂等；提交校验 source revision 与 job attempt，旧作业不得覆写新文档。检索只看 ready 且当前版本。删除先 tombstone，再撤索引/来源关系，并阻止在途 AI 把内容重新写回来。初期 SQLite jobs 表 + 同进程 worker 足够，不引入 Redis。

### 回答管线

```text
原始调用者授权 → scope → 关键词/未来向量召回 → 去重/topK
→ 上下文预算 → 模型 broker → 来源引用验证 → 回答/人工确认提议
```

当前仅实现关键词 topK 与来源摘录，`mode=local-extractive`，不调用 LLM，不声称语义检索。中文目前采用子串关键词匹配，不是中文分词 BM25。未来 embedding identity 必须包含 provider/model/dimension，变更后新建索引代际并重建，不能混合向量空间。

AI 修改必须携带 `expectedRevision + evidence + proposedPatch`，由宿主授权、结构检查和人工确认后提交。不能让模型的“保存工具”绕开版本冲突和审批。

## 6. 演进里程碑与退出标准

### M0：本地纵向原型（本次）

页面创建/保存/预览、官方插件启停、关键词检索、本地引用摘录、纯文本组件创建/模板使用/提交、内部受信审核与安装路径、SQLite 持久化、资源边界测试。仅供本地探索。

### M1：真正的个人 Wiki

- 页面树、链接/反链、删除恢复、Revision/CAS、历史恢复。
- 编辑自动保存防冲突、导入/导出 Markdown、附件对象存储边界。
- 用户可定制首页与首批 UI 槽，真正把组件组合进页面。
- 退出标准：数据能迁移、能恢复，并发保存不丢编辑。

### M2：多人平台与市场治理

- OIDC/会话、每用户多空间、成员授权、限流/配额、审计、迁移、备份恢复演练。
- 声明式组件 schema、不可变 release、审核后台、撤架/固定版本。
- 退出标准：跨租户读写/搜索/安装测试矩阵通过，审核不可越权。

### M3：可信 AI 知识循环

- source/jobs/provenance、引用定位与撤回、单模型网关、密钥托管。
- RAG、带引用生成、提议与人工确认；评测真实问题集，不只看“回答流畅”。
- 退出标准：旧任务不会复活删除内容；引用能回溯版本；预算可观测。

### M4：开放高级扩展

只有外部作者确有代码扩展需求才建设 SDK、包签名、独立隔离执行器、资源限制、故障熔断和升级回滚。不是为了理念先造一个操作系统。

## 7. 刻意不做

不复制 DSH 的 Profile/Bundle、多层 patch、客户端模块图、HMR 和完整 Slot 类型系统；不复制 WeKnora 的多检索引擎、OCR/ASR/图谱与多 worker 池；不在首版接入几十家模型、不搭 Kubernetes、不宣称已经拥有恶意插件沙箱。

**开放来自稳定边界与兼容承诺，不来自预先写出最多接口。**
