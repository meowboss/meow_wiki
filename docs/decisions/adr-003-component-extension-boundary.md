# ADR-003：用户组件开放边界与兼容协议

> 文档性质：决策记录：保留原始采纳/待评审语境，后续实现与替代关系须查当前状态。 [当前状态](<../status/current-status.md>) · [知识库入口](<../README.md>)

状态：提案，待评审。本文定义目标行为，不表示实验ComponentService已满足要求。

> 后继提案：[ADR-010全站插件画布](<adr-010-plugin-canvas.md>)不再以三类block作为新系统上限。本文保留v1兼容与旧首发取舍，代码隔离边界仍有效。

## 问题与备选

用户希望自行创造组件并经审核在市场分发。直接允许React/JavaScript可获得最大自由度，但同源UI或同进程服务器代码能接触用户身份和数据；审核、权限manifest、Worker都不能替代执行隔离。

- A：纯文本模板。安全与实现成本低，但只能复制内容，难以支撑专属页面组合。
- B：受约束声明式block组件（推荐首发）。支持静态内容与有限动态数据，宿主负责读取/授权/渲染。
- C：用户代码组件。自由度高，需要跨源隔离、受限RPC、资源预算、供应链和紧急吊销，单独里程碑。

## 推荐：B，同时兼容A

模板作为组件的一种内容用途，而不是第二套独立市场；代码扩展暂不纳入同一执行模型。官方插件仍可由受信代码提供新block renderer，但用户不能上传renderer代码。

### 第一版组件协议

概念形态：`{schemaVersion:1, name, description, blocks:[...]}`。字段约束与错误契约实施前落入共享schema，拒绝未知可执行字段。首批只定义真实用例需要的三类block：

- markdown：受控文本，经宿主净化渲染。
- page-list：读取使用者当前空间中的授权页面，可选择最近更新/固定同空间页面；有限数量与明确空状态。
- search：用户交互式搜索入口，只搜索当前授权空间。

不支持任意URL数据源、原始SQL、表达式求值、任意HTML、远程脚本或自定义CSS全局选择器。后续新增block必须有schema版本兼容与权限分析。

### 三个实际用例检验

1. 读书卡：静态Markdown提示+用模板新建页面，不必引入表单引擎。
2. 个人首页：简介Markdown+最近页面+搜索，验证动态读取使用者空间，不读作者空间。
3. 研究工作台：首版组合固定页面链接与检索；资料引用/AI草稿等block等知识模块成熟后再加，不提前设计万能状态机。

## 数据绑定和授权

发布快照不包含作者的私人页面正文、内部凭据或数据查询结果。动态block以安装者当前身份和空间执行，不能通过组件里的workspaceId切换域。固定页面引用在导出/发布时标记为本地绑定，安装者需要重新绑定；不可暗中读取作者资源。

首页布局引用本人草稿或本空间固定安装release。草稿内容变化可更新本人首页；公共安装使用不可变快照，不受作者后续编辑影响。布局自身有revision/CAS，避免两个标签页互相覆盖。

## 兼容、撤架与故障

- schema不支持：拒绝新安装，已有布局显示可移除占位，不执行未知内容。
- 一个block失败只影响该block，不使整个首页崩溃；错误显示不包含私人数据/内部堆栈。
- 一般撤架禁止新安装，保留已有快照；涉及安全的紧急吊销需要单独状态，禁用对应renderer/能力并解释原因，不把普通撤架和强制销毁混为一谈。
- 更新release需要用户确认，配置迁移失败保留旧安装与旧布局；不得自动写空默认值。
- 市场审核版本包含schema版本、内容摘要与许可声明；作者变更后必须重新提交。

## 验收

作者A创建私人读书卡→自己使用；未提交时B不可见；管理员C不能修改待审快照、只能作决定；批准后B安装并用于首页；组件动态列表只显示B的页面。A改草稿不影响B；不支持block/XSS输入/越权ID均有负例；新release升级失败仍可回到旧布局。

## 开放代码的未来路径

先通过真实作者需求证明声明式协议不足，再设计独立代码插件协议。可评估跨源iframe+受限RPC（UI）与受限进程/容器（服务器）；网络、文件、模型和数据访问均经宿主broker。签名证明来源与完整性，不证明代码无害。不得将代码执行作为schemaVersion小升级悄然开放。
