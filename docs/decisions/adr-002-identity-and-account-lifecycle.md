# ADR-002：身份、账号生命周期与管理员初始化

> 文档性质：决策记录：保留原始采纳/待评审语境，后续实现与替代关系须查当前状态。 [当前状态](<../status/current-status.md>) · [知识库入口](<../README.md>)

状态：选型已采纳Better Auth 1.7.20，正式接入尚待验收（2026-11-11）。已验证Node SQLite迁移与Fastify注册/会话/注销/来源拒绝；不采用实验AuthService作为长期密码系统。管理员、恢复和资源授权仍由应用层设计，不因库选型完成而视为已实现。

## 决策问题

多人Wiki需要的不只是登录接口，还包括注册策略、退出/撤销、账号恢复、封禁、管理员初始化、空间归属与部署迁移。认证库降低密码/协议实现风险，但不能代替资源授权；OIDC解决身份验证也不自动提供Wiki角色和数据隔离。

## 备选方案

| 方案 | 适合 | 收益 | 成本/风险 |
|---|---|---|---|
| 成熟认证库+数据库会话 | 无现成身份服务的自托管平台 | 可复用登录、会话、重置等机制 | 适配Fastify/React、数据库迁移、插件更新与安全维护仍需验证 |
| 外部OIDC优先 | 已有身份基础设施的组织/托管平台 | 密码与MFA由身份提供方承担 | 小型自托管部署复杂；需要明确subject绑定、登出和账号禁用语义 |
| 自建密码认证 | 极小封闭试运行 | 依赖少、完全控制 | 长期承担恢复、MFA、验证、封禁和漏洞响应；不因实验哈希测试通过就可靠 |

## 推荐方向

建立宿主Identity边界和自己的稳定User ID，优先验证一个成熟认证方案；在发布形态确定后选择“内建密码”或“OIDC”作为首个正式入口，不同时自建两套完整账号体系。Better Auth等可作为候选，但在完成维护状况、许可、Fastify适配、迁移与会话撤销验证前，不宣称已选定或已验证。若自托管要求零外部服务，可选成熟库的密码会话模式；若部署方已有OIDC则优先OIDC。

## 必须统一的应用语义

- User ID与登录名/邮箱/外部subject分开；改名不改变内容归属。
- OIDC身份唯一键为issuer+subject，不凭相同邮箱自动合并账号；绑定/解绑要求重新认证。
- 首期空间只有owner权限；平台审核员与空间owner是独立角色。
- 管理员由部署侧受信初始化命令/一次性凭证建立，不依赖公开用户名抢注，也不把第一个注册者自动升为管理员。
- 日常管理员不默认绕过私人知识授权；市场审核只读待审快照，不读作者整个空间。
- 用户封禁/密码重置撤销会话；修改敏感设置要求重新认证。

## 会话与浏览器边界

采用可撤销服务器会话，cookie HttpOnly、SameSite、生产HTTPS Secure；会话ID随机且服务端存摘要。写请求校验CSRF和可信Origin；路由规范化后按实际操作鉴权。前端不得在localStorage保存长期Bearer token。登录后轮换会话；会话数量/闲置与绝对到期策略明确配置。

密码/登录请求按IP、账号和全局并发限额保护；不能只锁账号而允许攻击者无限scrypt耗尽资源。错误避免暴露账号是否存在，管理员操作记录审计但不记录cookie、密码或恢复令牌。

## 注册、恢复与删除

- 单实例试运行推荐受控注册/邀请，管理员可配置开放注册；不是永久开放的无配额入口。
- 邮件可用时用一次性、短期、只存摘要的恢复令牌；邮件失败可重试但不能泄露账号存在性。
- 无邮件自托管模式采用部署管理员经审计重置或一次性恢复码；不能承诺“忘记密码自动恢复”。具体采用哪种需与首发运维方式一起确认。
- 账号删除前明确空间转移/导出/保留期；不级联误删市场已安装快照。会话先撤销，异步清理保留审计但避免无必要个人信息。

## 验证用例

1. 两用户同浏览器切换账号，缓存/草稿/空间/模型配置不混。
2. 过期、注销、封禁、重置后的旧会话全部不可访问。
3. 注册、登录、恢复均有限额；不存在账户与错误密码响应不泄露内部状态。
4. OIDC回调验证state/nonce/issuer/audience，绑定不能被邮箱碰撞接管（若选用OIDC）。
5. 未持受信初始化凭证不能获得管理员；审核员不能读取作者私人页。
6. 登录方案升级能在保留User ID与内容归属的前提下迁移，会话可以安全强制失效。

## 实施前退出条件

发布形态明确；候选认证库完成最小独立验证与安全维护审查；密码恢复/邮件依赖明确；生产cookie与代理信任模型明确；权限矩阵与浏览器验收用例列出。未达到这些条件，不把实验AuthService升级为正式平台身份模块。
