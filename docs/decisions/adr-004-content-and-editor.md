# ADR-004：内容真相、编辑器与页面版本

> 文档性质：决策记录：保留原始采纳/待评审语境，后续实现与替代关系须查当前状态。 [当前状态](<../status/current-status.md>) · [知识库入口](<../README.md>)

状态：待评审提案，不授权功能实现。

## 问题与备选

Wiki需要可靠编辑、版本恢复和插件渲染。Markdown纯文本便于携带但复杂交互有限；结构化富文本便于block编辑，但自定义节点往返Markdown可能丢失信息；同时维护两份可写真相会造成冲突。

## 推荐

首期页面以Markdown原文为唯一内容真相，元数据独立存储，渲染HTML为可重建缓存。声明式首页布局是独立的版本化结构，不塞进Markdown正文，也不把页面HTML当作存储格式。先用简单编辑器验证内容流程；确有语法编辑需求再选CodeMirror6。TipTap/Lexical等富文本方案需验证自定义节点导入导出后再单独决策，不为外观先引入。

## 版本契约

- Page保存当前revision指针和组织元数据；PageRevision不可变，保存标题、正文、父页/相关组织元数据、actor与操作。
- 修改带expectedRevision，在一个事务内检查并追加版本。历史恢复是追加新版本，不删除中间版本。
- 标题/父页变更同样受版本保护；父页同空间且防环，删除父页不级联删除子页。
- 删除为tombstone，检索排除，历史保留；回收站恢复时若原父页不可用则回根层并明确提示。
- 冲突不自动覆盖。首期展示本地内容与服务端新版本，由用户选择保留/合并；无需先做CRDT实时协同。
- 自动保存与手动保存使用同一CAS，不允许后台重试悄悄推进编辑基线。

## 链接、索引与插件

wiki链接语法及转义规则需要固定样本；同名页歧义需明确选择，不静默绑定第一条。反链由版本内容提取，为派生数据，可重建。链接解析永远在当前空间授权范围内，插件停用不破坏原文。HTML清洗策略属于宿主，不能由renderer自行关闭。

## 导入导出

导出Markdown、稳定ID映射、元数据与附件清单。文件名经过安全归一化且防重名；导入不信任原ID作为覆盖授权，默认生成新ID并重写包内链接。覆盖模式必须预览并明确版本确认。超限/不支持格式报错，不半导入静默丢内容；大导入走可恢复任务。

## 验收

金样本覆盖中文、代码块、表格、链接与恶意HTML；原文保存读取一致；版本冲突不丢本地内容；历史/删除/恢复可追溯；页面树防环；导出重导入后内容与内部链接可核对。若未来改用富文本，必须证明旧Markdown及插件扩展语法的迁移策略，不宣称天然无损。
